# 批注载荷消费端兼容范围

- Type: grilling
- Status: resolved
- Blocked by: none

## Question

`1.1.0` 的批注载荷必须在哪些消费端中保持可点击来源、代码高亮和嵌套引用，哪些消费端只要求保留可读的 Markdown 原文；当不同消费端的解析行为冲突时，以哪个消费端作为验收标准？

## Resolution

### 决策树

- **产品目标**：批注载荷面向通用 Agent，不使用 Codex、ChatGPT 或其他单一产品的专有指令或私有语法。
- **通用契约**：批注载荷使用标准、可读、自包含的 Markdown；Agent 不依赖链接跳转，也能从可见文字识别文件名、行号或行范围、所选文本和用户批注。
- **文件访问边界**：具备本地文件访问能力的 Agent 可以通过绝对路径打开文件；不具备该能力的 Agent 只要求正确理解批注载荷表达的来源和内容。
- **当前验收 Agent**：Codex 桌面端作为当前可实际验证的参考 Agent，验证语义识别和本地文件访问；这不把格式限定为 Codex 专用格式，也不构成对所有 Agent 产品逐一兼容的承诺。
- **普通 Markdown 消费端**：只要求载荷保持可读和结构明确；本地文件能否点击、代码高亮主题和引用样式不作为跨产品一致性契约。

以上由用户确认。
