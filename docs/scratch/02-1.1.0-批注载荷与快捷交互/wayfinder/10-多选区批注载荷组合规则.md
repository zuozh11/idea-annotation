# 多选区批注载荷组合规则

- Type: grilling
- Status: resolved
- Blocked by: ./04-来源链接与选区代码契约.md, ./05-Selected-text代码块与语言标识.md, ./06-User-comment文本边界.md, ./09-多光标选区模型与排序.md

## Question

多光标快捷复制时，哪些非空选区进入载荷、按什么顺序输出、相同或重叠选区是否保留，以及多个选区应组成一个载荷块还是用 `---` 分成多个块？

## Resolution

### 决策树

- **有效选区**：只处理具有非空选区的 Caret；同一编辑器中没有选区的 Caret忽略。至少存在一个非空选区时操作可用。
- **排列顺序**：按 `CaretModel.getAllCarets()` 提供的视觉位置顺序输出各组选区来源链接与代码块，不编号。
- **选区独立性**：不合并或去重相同、相邻及重叠选区；每个非空 Caret 分别生成一组“来源链接 + 代码块”。
- **单块结构**：全部组选区内容位于同一个外层 block quote 中，相邻组选区之间使用一个裸 `>` 行，不使用 `---` 分隔。
- **直接复制内容**：`Option+C` 输出上述单块多选区载荷，并在引用块之后保留空的 `_User comment:_` 标记。
- **原子复制**：先生成整份多选区批注载荷，再一次性写入剪贴板；全部成功或全部失败，不产生部分复制。
- **载荷 footer**：单光标和多光标载荷均在引用块之后输出 `_User comment:_`。非空评论前后各保留一个空行；空评论使用空模板留白。整份载荷只输出一次 `---`，footer 后保留一个空行，字符串固定以 `---\n\n` 结束。

以上由用户确认；无标题的重复选区组覆盖此前编号 `Selection` 方案，整份载荷底部仍固定保留一次 `---`。
