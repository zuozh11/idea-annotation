# 多光标选区模型与排序

- Type: research
- Status: resolved
- Blocked by: none

## Question

IntelliJ IDEA 2026.2 对同一编辑器内多个 Caret 的选区、主 Caret、创建顺序、文档顺序、空选区和重叠选区提供哪些稳定信息；为了确定多块批注载荷的顺序和有效选区集合，产品层必须锁定哪些规则？

## Resolution

### 平台事实

- `CaretModel.getAllCarets()` 返回当前编辑器的全部 Caret，并按编辑器中的视觉位置排序；该顺序可以作为批注块的稳定用户可见顺序。
- “主 Caret”如何确定不是平台稳定契约，JetBrains 明确说明当前实现虽是最近添加的 Caret，但未来可能变化，因此不能用主 Caret 或 Caret 创建顺序决定批注块顺序。
- 每个 Caret 独立提供 `hasSelection()`、`getSelectionStart()`、`getSelectionEnd()` 和所选文本。没有选区的 Caret 仍存在于 Caret 列表，需要由产品规则决定是忽略还是使操作不可用。
- 同一编辑器的多 Caret 共享同一 `Document` 和来源文件，因此每块批注的文件路径相同，但行号或行范围分别按各自选区计算。
- 平台 API 没有为插件提供“这些选区在产品语义上应合并或去重”的规则；相同或重叠范围如何处理属于批注载荷产品契约。

### 依据

- [JetBrains IntelliJ Platform `CaretModel`](https://github.com/JetBrains/intellij-community/blob/master/platform/editor-ui-api/src/com/intellij/openapi/editor/CaretModel.java)：`getAllCarets()` 按 visual position 返回；primary Caret 的确定方式未定义。
- [JetBrains IntelliJ Platform `Caret`](https://github.com/JetBrains/intellij-community/blob/master/platform/editor-ui-api/src/com/intellij/openapi/editor/Caret.java)：每个 Caret 独立暴露选区存在性和起止 offset。

结论：多块载荷应基于全部 Caret 的视觉顺序逐个读取非空选区，不依赖主 Caret；空选区、重复或重叠选区和分隔格式交给下一张票决定。
