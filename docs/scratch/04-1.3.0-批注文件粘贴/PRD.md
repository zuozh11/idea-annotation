# 批注文件粘贴 1.3.0 PRD

## Solution

Selection Annotation 的批注编辑框支持直接粘贴剪贴板中的文件、目录或原始图片。文件和目录使用其现有绝对路径，原始图片先保存为系统临时目录中的 PNG 文件；所有项目都在编辑框中显示为可整体操作、可点击的文件链接，并在确认批注时序列化为普通 Markdown 本地链接，使复制出的批注载荷可以继续交给 Codex、ChatGPT 或其他 Agent 读取对应本地资源。

## Scope

### Selection Annotation 范围

- 在批注编辑框中识别并粘贴一个或多个文件、目录及剪贴板原始图片。
- 将粘贴项目显示为不可拆分但可整体选择、复制和删除的文件链接。
- 支持从链接打开 IDEA 中的文件，或在 Project View 中定位目录。
- 将编辑框中的文件链接按确定格式写入最终批注评论及批注载荷。
- 为剪贴板原始图片生成可供后续读取的唯一 PNG 临时文件。
- 保持普通文本粘贴、手工输入和现有批注载荷结构不变。

### 涉及角色

- 在 IntelliJ IDEA 中把源码选区、补充说明和本地资源一起发送给 Codex、ChatGPT 或其他 Agent 的插件用户。

## Out of Scope

- 不显示图片缩略图、文件预览或通用附件卡片。
- 不支持拖放添加文件、文件选择器、附件管理面板或历史附件列表。
- 不把文件链接序列化为 Markdown 图片语法 `![名称](路径)`。
- 不自动解析或渲染用户手工输入、普通文本粘贴所得的 Markdown 链接。
- 不允许在原子链接内部直接编辑链接名称或目标路径。
- 不提供图片编辑、格式选择、放大预览、缓存管理或手动清理临时图片的功能。
- 不改变现有选区来源链接、代码块、共享评论、空白、footer 或其他批注载荷协议。
- 不包含版本号修改、签名、发布、Marketplace 上传或安装。

## User Stories

1. As a 插件用户, I want 在编写批注时直接粘贴文件或目录, so that 我不必手工输入资源名称和绝对路径。
2. As a 插件用户, I want 直接粘贴剪贴板中的图片, so that 图片可以作为 Agent 可读取的本地文件随批注一起引用。
3. As a 插件用户, I want 在编辑框中看到可点击的文件链接, so that 我能在复制批注前确认链接对应的本地资源。
4. As a 插件用户, I want 文件链接与普通批注文字自由混排, so that 一条批注可以同时表达说明和多个本地资源。

## Requirements

### 剪贴板内容识别

#### Selection Annotation 逻辑

- 用户在批注编辑框中执行粘贴时，必须按“文件或目录列表、原始图片数据、普通文本”的优先级识别剪贴板内容。
- 剪贴板包含一个或多个文件或目录时，必须按剪贴板提供的顺序处理全部项目；目录与普通文件具有相同的粘贴资格。
- 同一图片同时以已有文件和原始图片数据提供时，必须只使用已有文件路径，不得重复插入链接或生成临时文件。
- 剪贴板不包含文件、目录或原始图片时，必须继续执行现有普通文本粘贴，不得改变文本内容。
- 只有通过上述剪贴板项目识别流程插入的项目才显示为渲染后的文件链接。手工输入或普通文本粘贴中的 Markdown 必须保持可编辑原文，不自动转换。

### 文件与目录链接插入

#### Selection Annotation 逻辑

- 文件和目录必须使用粘贴时的绝对路径作为链接目标。
- 非图片文件的链接名称必须使用文件名；目录的链接名称必须使用目录名；已有图片文件与原始图片共享本次批注输入会话的 `Image 1`、`Image 2`……顺序名称。
- 文件链接必须插入当前光标位置，允许与用户已有文字及其他链接混排，不得改写已有内容。
- 一次粘贴多个项目时，每个链接必须独占一行，并按剪贴板顺序排列。
- 插入过程只可补足链接与相邻内容之间必要的换行，不得增加其他占位文字。
- 编辑框中的文件链接必须作为不可拆分的原子元素呈现。用户可以整体选择、复制或删除该元素，但不能在元素内部直接编辑名称或路径。

### 剪贴板原始图片落盘

#### Selection Annotation 逻辑

- 剪贴板包含原始图片且没有更高优先级的文件或目录列表时，插件必须先把图片保存为 PNG 文件，再插入对应文件链接。
- 临时图片必须写入当前系统临时目录，并使用 `selection-annotation-clipboard-<唯一值>.png` 形式的唯一文件名，避免覆盖既有文件。
- 已有图片文件与临时图片的链接名称必须在每次批注输入会话中按粘贴顺序共同使用 `Image 1`、`Image 2`……，不得向用户显示真实或随机图片文件名。
- 临时图片在批注编辑框关闭、插件退出或批注复制完成后不得由插件主动删除；其后续清理由系统临时目录策略负责。
- 临时图片写入成功后，其链接行为必须与已有图片文件一致；本次不显示图片缩略图或内容预览。

### 链接点击与失效反馈

#### Selection Annotation 逻辑

- 用户点击文件链接时，插件必须在当前 IDEA 中打开对应文件。
- 用户点击目录链接时，插件必须在当前 IDEA 的 Project View 中定位对应目录。
- 链接点击不得关闭批注编辑框、确认批注或改变编辑框中的文字与链接顺序。
- 链接对应的文件或目录在点击时不存在或不可访问时，插件必须保留该链接，并在批注编辑框内提示“文件或目录不存在”。
- 链接失效不得自动删除链接、修改目标路径或阻止用户继续编辑及确认批注。

### 批注载荷序列化

#### Selection Annotation 逻辑

- 用户确认批注时，每个原子文件链接必须在其当前位置序列化为普通 Markdown 链接：`[名称](/绝对路径)`。
- 文件、目录和临时图片均不得使用 Markdown 图片语法。
- 链接名称和目标路径必须沿用现有 Markdown 链接的转义规则，包括名称中的方括号、路径中的空格、括号及尖括号边界。
- 序列化后的链接属于用户评论正文；其前后普通文字、换行及多个链接的顺序必须与编辑框中的可观察内容一致。
- 文件链接使评论成为非空评论时，最终结果必须继续使用现有非空评论批注载荷；不得为文件额外增加附件区、预览区或独立 footer。

### 失败处理

#### Selection Annotation 逻辑

- 原始图片无法写入临时文件时，不得插入无效链接或改动编辑框已有内容，并必须在编辑框内显示错误。
- 一次粘贴多个文件或目录时，各项目必须独立处理；可用项目照常插入，失败项目不插入，并以一条汇总错误提示告知本次存在失败项。
- 单个项目处理失败不得关闭批注编辑框，也不得阻止用户继续编辑、再次粘贴、取消或确认已经存在的有效内容。

## Implementation Decisions

### 锁定决策

| 决策项 | 决策值 | 来源 |
| --- | --- | --- |
| 粘贴项目范围 | 支持一个或多个文件及目录，并保持剪贴板顺序 | 用户确认 |
| 原始图片 | 保存为系统临时目录中的唯一 PNG 文件 | 用户确认 |
| 临时文件生命周期 | 插件不主动删除，由系统临时目录策略清理 | 用户确认 |
| Markdown 形式 | 文件、目录和图片统一输出普通链接，不使用图片语法 | 用户确认 |
| 链接名称 | 非图片文件和目录使用真实名称；已有图片文件与原始图片在每次批注输入会话中共同按顺序使用 `Image 1`、`Image 2`…… | 用户确认 |
| 插入位置 | 插入当前光标位置，多项目各占一行，可与普通文字混排 | 用户确认 |
| 编辑框呈现 | 不显示图片预览；粘贴项目显示为不可拆分的原子文件链接 | 用户确认 |
| 链接点击 | 文件在 IDEA 中打开，目录在 Project View 中定位 | 用户确认 |
| 渲染范围 | 仅渲染通过文件、目录或原始图片剪贴板流程插入的项目 | 用户确认 |
| 剪贴板优先级 | 文件或目录列表优先于原始图片，原始图片优先于普通文本 | 用户确认 |
| 失效链接 | 保留链接和最终 Markdown，点击时提示不存在 | 用户确认 |
| 失败边界 | 成功项保留、失败项跳过并提示；图片落盘失败不改动已有内容 | 用户确认 |
| 载荷协议 | 文件链接只进入现有评论正文，不改变批注载荷其他结构 | 用户确认 / RULE A03 |
