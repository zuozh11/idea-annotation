# 整行选区链接化 1.2.0 PRD

## Solution

Selection Annotation 在生成 Markdown 时识别完整覆盖一行或连续多行有效内容的选区。当所有有效选区均为整行且评论为空时，剪贴板仅接收带行号的来源链接；需要承载评论或存在行内选区时，继续生成一份批注载荷，但整行选区组不再附带代码块。行内选区的预处理、代码块和评论协议保持 `1.1.2` 行为。

## Scope

### Selection Annotation 范围

- 在批注上下文中按 Caret 识别无效选区、整行选区和行内选区。
- 为全部整行且空评论的上下文输出带行号的独立链接。
- 在非空评论或混合选区载荷中省略整行选区的代码块。
- 保持多 Caret 视觉顺序、共享评论、链接行号和现有入口的一致性。

### 涉及角色

- 在 IntelliJ IDEA 中把源码选区复制给 Codex、ChatGPT 或其他 Agent 的插件用户。

## Out of Scope

- 不改变行内选区的文本预处理、动态围栏、语言标识或代码块格式。
- 不新增兼容开关、设置项、菜单入口、复制提示或旧载荷模板。
- 不合并、去重或拆分相邻、重叠及包含内部空白行的多 Caret 选区。
- 不改变路径转义、文件标签、剪贴板写入、输入框生命周期或成功与失败反馈。
- 不包含版本号修改、签名、发布、Marketplace 上传或安装。

## User Stories

1. As a 插件用户, I want 完整行选区仅保留来源链接, so that Agent 能直接读取对应行而不必接收重复代码。
2. As a 插件用户, I want 整行空评论结果不包含占位和收尾结构, so that 粘贴结果与文件 Copy 一样紧凑。
3. As a 插件用户, I want 整行与行内选区能按原顺序共存于一份批注载荷, so that 一条共享评论能清晰对应所有来源。
4. As a 插件用户, I want 直接复制和确认空评论使用同一格式, so that 输出不因操作入口而变化。

## Requirements

### 有效选区与整行识别

#### Selection Annotation 逻辑

- 每个非空 Caret 选区必须独立执行现有预处理：删除首部和尾部所有连续空白行，再移除剩余非空行共有的最长前导空白前缀。
- 预处理中的空白行和缩进字符仅指 ASCII 空格与 Tab；不扩展到 Unicode 空白或全角空格。
- 预处理后不含任何有效内容的 Caret 选区必须视为无效选区。它与有效选区并存时被忽略；全部 Caret 选区均无效时，当前编辑器等同没有文本选区。
- 预处理后仍有内容的选区在同时满足以下条件时必须识别为整行选区：
  - 首个有效行的选区起点位于该行前导缩进区域的任意位置，或位于首个非空字符；
  - 最后一个有效行被选到实际行尾；非空行尾的空格与 Tab 也必须实际包含在选区中；
  - 首尾之间的物理行被完整包含。
- 是否额外选中最后一行的行尾换行符不影响整行判定，也不得把下一行计入链接范围。
- 有效范围中的中间空白行必须保持在同一个连续整行范围中，不得拆分链接。
- 任一有效选区未完整覆盖上述内容边界时，必须作为行内选区并完全沿用 `1.1.2` 格式。
- 来源链接的起止行号必须继续根据原始 selection offsets 计算，不得因预处理删除首尾空白行而收缩。

### 无有效选区的入口行为

#### Selection Annotation 逻辑

- 当前编辑器没有有效选区时，直接上下文复制必须输出当前文件的无行号独立路径链接。
- 单项无行号链接必须继续使用一个前导 ASCII 空格和一个尾随 ASCII 空格。
- 当前编辑器没有有效选区时，“批注…”入口必须与真正没有选区时一致，不得打开评论输入框。
- 多 Caret 中只要存在一个有效选区，“批注…”入口仍必须可用，并忽略其他无效选区。

### 全部整行且空评论

#### Selection Annotation 逻辑

- 评论必须继续先执行现有首尾空白删除；空字符串或处理后为空的评论均属于空评论。
- 当所有有效选区均为整行且评论为空时，结果必须只包含带行号的来源链接，不得包含 block quote、代码块、`_User comment:_`、footer 或其他占位结构。
- 单个整行选区的精确结果必须为“一个前导 ASCII 空格 + 一条带行号链接 + 一个尾随 ASCII 空格”，不得包含换行。
- 多个整行选区必须按 Caret 视觉顺序输出链接，相邻链接之间只使用一个 `\n`；整体不得包含前导空格、尾随空格或尾随换行。
- 相同、相邻或重叠的整行选区必须保持 Caret 独立性，不得合并或去重。

### 批注载荷组合

#### Selection Annotation 逻辑

- 当评论非空，或至少存在一个行内选区时，所有有效选区必须组合为一份批注载荷。
- 每份批注载荷必须以一个 `\n` 开头，使粘贴结果的首行为空白行。仅输出独立路径链接或“全部整行且空评论”链接的结果不属于批注载荷，不增加该换行。
- 批注载荷中的整行选区组必须只输出 block quote 内的带行号来源链接，不得输出代码块。
- 行内选区组必须完全沿用 `1.1.2` 的“block quote 内来源链接 + 动态 fenced code block”格式。
- 整行与行内选区可以位于同一份载荷中；所有有效选区必须按 Caret 视觉顺序排列，相邻组之间继续使用一个裸 `>` 行。
- 批注载荷只能输出一条共享评论，位于所有选区组之后。
- 最后一个选区组结束后必须额外输出一个 `\n`，使 `_User comment:_` 上方保留一个空白行；精确边界为“最后一个选区组的行尾 `\n` + 额外一个 `\n` + `_User comment:_`”。
- 非空评论必须沿用 `1.1.2` 精确收尾：`_User comment:_\n\n<comment>\n\n---\n\n`。
- 当载荷中存在行内选区且评论为空时，必须沿用 `1.1.2` 空评论收尾：`_User comment:_\n\n\n\n---\n\n`。
- 直接上下文复制与打开输入框后确认空评论，必须对同一批注上下文生成完全相同的 Markdown。
- 链接文本、绝对路径目标、Markdown 转义和单行与多行行号标签必须继续沿用现有协议。

## Implementation Decisions

### 锁定决策

| 决策项 | 决策值 | 来源 |
| --- | --- | --- |
| 整行判定 | 按预处理后的有效内容覆盖判定，不要求原始选区从物理行首开始 | 用户确认 |
| 缩进内起点 | 起点在前导缩进区域任意位置均可识别为整行 | 用户确认 |
| 空白定义 | 仅 ASCII 空格与 Tab；非空行尾随空白必须实际选中 | 用户确认 |
| 纯空白选区 | 视为无有效选区；全部无效时退回无行号文件链接 | 用户确认 |
| 中间空白行 | 保持在一个连续整行范围中 | 用户确认 |
| 链接行号 | 使用原始 selection offsets，不随预处理收缩 | 用户确认 / RULE A03 |
| 全部整行且空评论 | 只输出带行号链接，外壳沿用单项或多项独立路径链接 | 用户确认 |
| 整行且非空评论 | 保留批注载荷、共享评论和 footer，仅删除整行代码块 | 用户确认 |
| 混合选区 | 整行组与行内组共存于一份载荷 | 用户确认 |
| 多 Caret 范围 | 保持视觉顺序和独立性，不合并、不去重 | 用户确认 |
| 空评论入口 | 直接复制与输入框确认结果完全一致 | 用户确认 |
| 批注载荷空行 | 载荷以一个空白行开头，且 `_User comment:_` 上方保留一个空白行；纯链接结果不受影响 | 用户确认 |
| 产品范围 | 不新增设置、入口、提示或兼容模板 | 用户确认 / 最小实现规则 |
