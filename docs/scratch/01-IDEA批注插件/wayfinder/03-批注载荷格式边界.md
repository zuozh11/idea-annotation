# 批注载荷格式边界

- Type: grilling
- Status: resolved
- Blocked by: none

## Question

批注载荷应如何精确定义换行、空白、Markdown 引用前缀、空评论、尾随换行以及多行选区和多行评论的序列化结果？

## Resolution

### 决策树

- **所选文本保真**：除 IntelliJ `Document` 已统一使用 `\n` 外，保留选区的缩进、空行、首尾空格与首尾换行。
  - **多行引用**：所选文本的每个物理行都添加 `> ` 前缀；选区末尾换行产生的空行也保留为 `> `。
- **批注规范化**：保留内部换行、缩进和空格，只去除整个批注首尾的空白。
  - **空批注**：允许；仅包含空白的输入经处理后视为空批注，仍可复制。
  - **多行引用**：非空批注的每个物理行都添加 `> ` 前缀。
- **结构空行**：三个章节之间统一使用一个裸 `>`，不使用 `>  `。
- **载荷结尾**：`User comment` 后以一个裸 `>` 结束，整个载荷末尾保留恰好一个 `\n`。

### 非空批注示例

```markdown
> **Source:**
> /project/src/Example.java:12-13
>
> **Selected text:**
> first line
>     second line
>
> **User comment:**
> 第一行
> 第二行
>
```

### 空批注示例

```markdown
> **Source:**
> /project/src/Example.java:12
>
> **Selected text:**
> selected text
>
> **User comment:**
>
```

以上两个示例在最后一个 `>` 后均包含且只包含一个换行符。
