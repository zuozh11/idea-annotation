# 批注入口与交互流程

- Type: prototype
- Status: resolved
- Blocked by: ./01-IntelliJ平台能力与兼容基线.md

## Question

在 IDEA 中，选中文本后应通过什么入口触发批注，输入框如何出现、聚焦、确认和取消，复制成功后如何反馈，才能在平台能力内最小化复刻截图中的 Codex 批注体验？

## Resolution

交互原型：[IDEA 批注交互原型](../prototype/annotation-flow-prototype.html)

当前提供三个可切换变体：

- A：右键菜单 + 标准对话框；平台原生、实现最小。
- B：所选文本右上角小胶囊 + 就地浮层，并保留右键菜单入口；在尽量少遮挡选区的前提下接近 Codex 体验。
- C：编辑器动作 + 右侧面板；保持代码上下文可见，但占用编辑区域。

### 用户选择

采用 **B：选中文本右上角小胶囊 + 就地浮层**，同时保留 **A：编辑器右键菜单中的“批注…”** 作为始终可用的入口。不调用平台内部的 `CodeFloatingToolbar`，只使用公开 Action 与 Popup API。

### 可行性证据

已直接检查本机 IntelliJ IDEA `2026.2.1 / 262.9437.185` 的公开类签名，以下能力均存在：

- `SelectionModel.addSelectionListener(...)` 与 `EditorEventMulticaster.addSelectionListener(...)`：监听选区变化；JetBrains 当前公开源码也保留该接口：[SelectionModel](https://github.com/JetBrains/intellij-community/blob/master/platform/editor-ui-api/src/com/intellij/openapi/editor/SelectionModel.java)。
- `Editor.offsetToXY(...)` / `visualPositionToXY(...)`：把选区末端转换为编辑器内容坐标。
- `RelativePoint(editor.getContentComponent(), point)` 与 `JBPopup.show(RelativePoint)`：把 Popup 锚定到选区旁；JetBrains 自身也使用同一坐标组合定位编辑器 Popup：[ColorPicker](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/ui/ColorPicker.java)。
- `JBPopupFactory.createComponentPopupBuilder(...)`、`setRequestFocus(...)`、`setCancelOnClickOutside(...)`：分别创建不抢焦点的入口胶囊和可输入的批注浮层；这是官方推荐的通用自定义 Popup 路径：[Popups](https://plugins.jetbrains.com/docs/intellij/popups.html)。
- `JBPopupFactory.createHtmlTextBalloonBuilder(...)`：复制成功后显示短暂成功反馈。

### 最终交互流程

1. 用户完成文本选择后，在所选文本的右上角出现尽量小的“批注”胶囊；胶囊不抢编辑器焦点、不清除选区，并与高亮区域保持小间距。
2. 单行选区以选区右端定位；多行选区以第一条被选中可视行的右端作为右上角。位置超出编辑器可视区域时向内调整。
3. 点击胶囊后关闭入口 Popup，在选区右上角附近打开多行批注浮层并立即聚焦输入框。
4. 对有效选区点击右键时，菜单始终提供“批注…”；无论胶囊设置是否关闭、当前选区的胶囊是否被抑制，都能从右键菜单打开同一个输入浮层。
5. `Esc`、点击外部或“取消”关闭浮层，不写剪贴板；取消后若胶囊设置开启，当前选区仍显示胶囊。
6. 点击“复制”后生成批注载荷、写入剪贴板并关闭浮层，短暂显示“批注已复制”；当前选区不立即重新显示胶囊，选区变化后恢复。右键菜单不受该抑制影响。
7. 同一编辑器同时只保留一个入口 Popup 或输入 Popup；鼠标拖选结束后显示入口，键盘扩展选区时在选区稳定后显示，避免拖选过程闪烁。滚动编辑器时重新计算位置或关闭胶囊，避免悬空。

结论：右上角小胶囊和右键 Action 可以共用同一输入浮层与载荷生成逻辑；所需能力均为稳定公开 API，调用链短，没有技术阻塞，可以顺畅实现。
