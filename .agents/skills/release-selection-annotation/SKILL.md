# 发布 Selection Annotation

先运行项目知识 `scope` 并加载证据交付场景 `C`；维护 README 或发布证据时再加载 `D`。随后完整读取 `AGENTS.md`、`docs/publishing.md` 和当前 `.github/workflows/`。本 Skill 不缓存版本号、兼容范围、Job 名称、Marketplace 状态或工作流形状。

## 选择模式

- 用户明确要求发布、推送稳定标签或发布并安装时，执行稳定发布。
- 用户明确要求重建或刷新 Actions 缓存时，只执行缓存重建。
- 准备发布、检查流程或查看状态只允许准备与只读核对，不授权推送标签或触发外部副作用。

## 稳定发布

1. **固定交付单元**
   - 核对当前分支、工作区、远端、已有标签和发布配置。
   - 从当前 Gradle 配置读取版本，并按发布指南确认同一版本所需的说明与变更记录已经形成完整提交。
   - 普通提交与 push 按用户授权执行；不要把稳定标签包含在普通 push 的默认含义里。

2. **发布授权门**
   - 仅当当前请求明确授权发布或推送稳定标签时继续。
   - 按当前工作流要求创建新的稳定标签并推送；不移动、复用或重写已经产生发布副作用的标签。

3. **跟随当前工作流**
   - 找到本次标签对应的真实 Actions run，按当前工作流核对实际任务、产物和副作用。
   - 失败或响应含糊时，先判断 Marketplace 是否已经收到该版本，再选择只重跑安全阶段或发布新版本，避免重复上传。

4. **收口证据**
   - 分别确认标签指向、构建与签名结果、GitHub Release 资产、Marketplace 上传接受和当前审核/公开状态。
   - 按 `docs/publishing.md` 当前格式记录 URL、状态与时间。README 只在稳定用户能力发生变化时更新。
   - 用户要求安装时，从本次正式 GitHub Release 获取签名 ZIP，安装到当前 IDEA 使用的插件目录，并说明当前进程是否需要重启。

## 重建共享缓存

缓存重建不是发布的固定步骤。只有用户明确要求时，才按当前 Build 工作流允许的 ref 和入口触发；持续等待真实 run 结束，并从日志确认缓存写入结果与未发生发布副作用。

## 完成标准

- **稳定发布**：当前发布指南要求的版本、提交、标签、工作流、正式资产、外部状态与证据台账相互一致；用户要求的安装已完成。
- **缓存重建**：当前配置对应的重建 run 成功，日志证明缓存已保存且没有发布副作用。
- 报告仍由 JetBrains 控制的审核或公开状态，不把等待外部审核当成本地未完成工作。
